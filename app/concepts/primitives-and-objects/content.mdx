## 동작 원리

자바스크립트의 값은 **원시 값**과 **객체** 두 종류로 나뉩니다. 원시 값은 숫자(number), 문자열(string), 불리언(boolean), undefined, null, bigint, symbol의 일곱 가지 타입이고, 그 밖의 값은 모두 객체입니다.

원시 값은 바꿀 수 없습니다(불변). 숫자 10을 11로 고치는 방법은 없고, 변수에 다른 값을 넣을 수 있을 뿐입니다. 반면 객체는 바꿀 수 있습니다(가변). 프로퍼티를 추가하거나, 값을 바꾸거나, 지울 수 있습니다.

그래서 변수를 다룰 때는 두 가지 동작을 구분해야 합니다.

- **재할당**: `x = 새 값`처럼 변수가 가진 값을 다른 값으로 바꿉니다. 영향을 받는 것은 그 변수 하나뿐입니다.
- **변경**: `x.n = 새 값`처럼 변수가 가진 객체의 내용을 바꿉니다. 같은 객체를 값으로 가진 모든 변수에서 그 변화가 보입니다.

`let b = a`나 `b = a`처럼 변수에 값을 넣으면, 오른쪽의 `a`를 평가한 값이 `b`에 들어갑니다. `a`의 값이 객체라면 `b`도 **같은 객체**를 값으로 갖게 되고, 새 객체는 만들어지지 않습니다.

흔히 "원시 값은 복사되고 객체는 참조가 복사된다"고 설명합니다. 하지만 원시 값은 바꿀 수 없으므로, 복사된 것인지 같은 값을 함께 쓰는 것인지 코드로는 구분할 수 없습니다. 결과의 차이를 실제로 만드는 것은 **재할당이냐 변경이냐**입니다.

예제 1에서 `b`와 `q`는 재할당만 되었기 때문에 `a`와 `p`는 그대로입니다. 예제 2에서는 `p`와 `q`가 같은 객체를 가진 상태에서 그 객체가 변경되었기 때문에 `p.n`도 2가 됩니다. 예제 3의 함수 안에서 일어난 일도 같은 규칙으로 설명됩니다. `obj.n = 99`는 변경이라 `o`에서도 보이고, `num = 99`와 `obj = { n: 0 }`은 매개변수의 재할당이라 호출한 쪽에 영향이 없습니다.

<Callout type="misconception" title="객체를 다른 변수에 넣으면 객체가 복사된다">
  변수에 객체를 넣어도 새 객체는 만들어지지 않습니다. `const q = p` 뒤에 `p`와 `q`는 같은 객체를
  값으로 가지며, 이는 `p === q`가 `true`인 것으로 확인할 수 있습니다. 별도의 객체가 필요하다면
  객체를 새로 만들어야 합니다.
</Callout>

<Callout type="misconception" title="const로 선언한 객체는 바꿀 수 없다">
  `const`는 변수의 **재할당**만 막습니다. `const q`라도 `q.n = 2`처럼 q가 가진 객체를 변경하는 것은
  허용됩니다.
</Callout>

<Callout type="misconception" title="객체를 함수에 넘기면 참조에 의한 전달(call by reference)이다">
  자바스크립트는 인수를 평가한 값을 매개변수에 넣습니다. 객체를 넘기면 그 값이 같은 객체이므로 변경은 호출한 쪽에서도 보입니다. 하지만 매개변수를 재할당해도 호출한 쪽 변수는 바뀌지 않습니다. 만약 참조에 의한 전달이었다면 예제 3의 `obj = { n: 0 }` 뒤에 `o`도 새 객체를 가리켰을 것입니다.
</Callout>

### 메모리 그림으로 배운 내용과의 관계

많은 자료가 이 내용을 메모리 주소와 스택·힙 그림, "값에 의한 전달"과 "참조에 의한 전달"이라는 용어로 설명합니다. 이 페이지는 명세가 보장하는 관찰 가능한 동작만으로 설명합니다. 그림의 "같은 메모리 주소를 가리킨다"는 이 페이지의 "같은 객체를 값으로 가진다"(같은 `객체 A`)에 해당합니다. 다만 명세는 메모리 주소나 스택·힙을 정의하지 않으므로, 엔진이 실제로 그렇게 값을 저장한다고 단정할 수는 없습니다.
