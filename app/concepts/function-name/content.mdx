`const o = {}`를 만들고 `o.p = () => {};`를 실행하면 `o.p.name`은 `'p'`가 아니라 빈 문자열입니다. 같은 화살표 함수를 `const f = () => {};`로 초기화하면 `f.name`은 `'f'`인데 왜 다를까요? 함수의 `name`은 함수를 만들 때 정해지는 자기 프로퍼티이고, 명세는 익명 함수 정의가 바인딩의 초기화식이나 왼쪽이 식별자인 대입의 오른쪽에 바로 있을 때 그 이름을 넘겨 함수를 만들게 합니다. 리터럴의 `키: 값`에서는 값이 익명 함수 정의일 때 키를 넘기고, 메서드·getter·setter는 항상 키로 이름을 정합니다. `o.p = () => {}`는 대입식의 왼쪽이 식별자가 아니라서 이름을 넘기지 않고, 이렇게 만든 화살표 함수의 `name`은 빈 문자열입니다. 이 페이지는 이 규칙을 예제 다섯 개로 확인합니다. [함수를 정의하는 방법](/concepts/function-definitions), [프로퍼티 어트리뷰트와 접근자](/concepts/property-attributes), [화살표 함수와 메서드 축약](/concepts/arrow-functions)을 전제합니다.

## 동작 원리

### name은 만들 때 정해진다

함수의 `name`은 함수를 만드는 동안 명세의 SetFunctionName이 정하는 자기 프로퍼티입니다. 어트리뷰트는 `writable: false`, `enumerable: false`, `configurable: true`입니다(예제 5의 4번 줄). 이름을 받지 못한 익명 함수도 값이 빈 문자열인 자기 `name` 프로퍼티를 가집니다(예제 5의 20~21번 줄). "이름 추론"은 널리 쓰는 표현이지만 명세의 용어는 아니며, 명세는 이를 NamedEvaluation(이름을 넘겨 평가하기)과 SetFunctionName으로 정의합니다. 함수의 또 다른 프로퍼티인 `length`는 [매개변수 기본값](/concepts/default-parameters)에서 다룹니다.

### 이름을 넘겨받는 자리

익명 함수 정의(이름 없는 `function` 식과 화살표 함수. 이름 없는 제너레이터·async 함수 식과 클래스 식도 같습니다)가 아래 자리에 바로 있으면 명세는 그 자리의 이름을 SetFunctionName에 넘겨 함수를 만듭니다.

- `var`·`let`·`const`의 초기화식과 매개변수 기본값: 바인딩 이름
- 왼쪽이 식별자인 `=` 대입의 오른쪽: 그 식별자의 이름
- 객체 리터럴의 `키: 값`: 값이 익명 함수 정의일 때 그 키

예제 1의 2번 줄 `function decl() {}`는 함수 선언이라 선언에 쓴 이름 `decl`을 씁니다. 3번 줄 `var v = function () {};`와 4번 줄 `let arrow = () => {};`는 초기화식이 익명 함수 정의라 `v`와 `arrow`를 받습니다. 5~6번 줄은 `let later;`로 선언만 하고 6번 줄에서 대입했는데도 `later`입니다. 대입식의 왼쪽이 식별자이고 오른쪽이 익명 함수 정의이기 때문입니다. 7~9번 줄은 인수 없이 `withDefault()`를 불러 기본값이 쓰이게 한 것이며, 매개변수 기본값도 바인딩의 초기화식이라 `cb`를 받습니다. `||=`·`&&=`·`??=`도 왼쪽이 식별자이면 같은 방식으로 이름을 넘기지만 예제로 보이지는 않습니다.

리터럴에서는 `키: 값`의 값이 익명 함수 정의일 때 그 키가 이름이 됩니다. 예제 2의 3번 줄 `prop: () => {}`가 `prop`을 받는 경우입니다. 메서드 축약 `method() {}`는 [화살표 함수와 메서드 축약](/concepts/arrow-functions)에서 다루며, 항상 키를 이름으로 삼습니다. getter와 setter는 키 앞에 `get `·`set `을 붙인 이름이 됩니다. getter는 프로퍼티를 읽으면 실행되어 반환값이 나오므로(예제 2의 `o.size`가 `1`) 함수 자체는 `Object.getOwnPropertyDescriptor`로 꺼내서 `name`을 읽습니다. 이름은 소스에 쓴 글자가 아니라 키 문자열입니다. 숫자 키 `1.50`의 이름은 `"1.5"`이고, 계산된 키 `['item' + 1]`의 이름은 계산 결과인 `"item1"`입니다.

### 이름을 넘겨받지 못하는 자리

이름을 넘기는 두 조건은 "대입이라면 왼쪽이 식별자인가"와 "오른쪽 식이 익명 함수 정의 그 자체인가"입니다. 예제 3의 3~4번 줄 `o.p = () => {}`와 `o['q'] = function () {}`는 왼쪽이 프로퍼티 접근이라 식별자가 아니므로(명세의 IsIdentifierRef가 false) 이름을 넘기지 않고 `name`이 빈 문자열입니다. 인수 자리도 같습니다. 6~9번 줄에서 `take(() => {})`로 넘긴 화살표 함수는 인수 식을 평가할 때 이미 만들어지며 그 자리는 이름을 넘기지 않으므로, 매개변수 `fn`으로 전달된 뒤에도 `name`은 빈 문자열입니다.

오른쪽 식이 함수 정의 그 자체가 아니면 이름을 넘기지 않습니다. 함수 정의인지는 실행 중 값이 아니라 코드의 모양으로 정해집니다. 11번 줄의 `(0, function () {})`는 쉼표 식이고, 12번 줄의 `null || function () {}`는 `||` 식입니다. `||`는 왼쪽이 `null`이라 오른쪽 피연산자를 평가해 그 값을 돌려주지만(`||`의 동작은 [단축 평가](/concepts/short-circuit-evaluation)에서 다룹니다) 식 전체는 함수 정의가 아니라서 둘 다 `name`이 빈 문자열입니다. 삼항 식, 대입식, `new` 식도 함수 정의가 아닙니다. 괄호는 다릅니다. 10번 줄의 `const paren = (function () {});`처럼 오른쪽 식을 감싼 괄호는 함수 정의를 그대로 통과시켜 `paren`을 받습니다. 오른쪽 식에서만 그렇고, 대입의 왼쪽을 괄호로 감싸는 경우는 다루지 않습니다.

이미 있는 함수나 이미 이름이 있는 함수 정의는 이름을 넘겨받지 않습니다. 예제 4의 3번 줄 `const copy = original;`은 새 함수를 만들지 않고 이미 있는 함수를 가리킬 뿐이라 `name`은 만들 때 정해진 `original`입니다. 5번 줄의 `function inner() {}`는 자기 이름이 있는 함수 정의라 `const named`의 `named`를 받지 않고 `inner`입니다. 이 이름은 함수 안에서 쓰는 이름 바인딩이기도 한데 이는 [함수를 정의하는 방법](/concepts/function-definitions)에서 다루며 `name` 프로퍼티와는 별개의 동작입니다. 8번 줄 `a = b = function () {};`에서는 `a`의 오른쪽 `b = function () {}`가 대입식이라 함수 정의가 아니고, 안쪽 대입에서 함수가 `b`라는 이름으로 만들어집니다. 그래서 `a`와 `b`는 같은 함수를 가리키고 `name`은 둘 다 `b`입니다. 10번 줄 `new Function('return 1')`로 만든 함수는 CreateDynamicFunction이 `anonymous`로 정합니다.

### name을 바꾸는 방법

`name`은 `writable: false`라 대입으로는 바꿀 수 없습니다. 이런 막힌 대입은 sloppy mode에서는 아무 일도 하지 않고 strict mode에서는 TypeError입니다([프로퍼티 어트리뷰트와 접근자](/concepts/property-attributes)). 예제 5의 5번 줄 `f.name = 'z';` 뒤 6번 줄은 여전히 `"f"`이고, 본문 첫 줄이 `'use strict';`인 `setInStrict()`의 같은 대입은 `TypeError`입니다([strict mode](/concepts/strict-mode)).

`configurable: true`이므로 `Object.defineProperty`로 다시 정의하거나 `delete`로 지울 수 있습니다([프로퍼티 어트리뷰트와 접근자](/concepts/property-attributes)). 16번 줄처럼 `defineProperty`로 `name`을 `'z'`로 정하면 17번 줄에서 `f`의 `name`은 `"z"`입니다. `bind`는 `bind`하는 순간 대상 함수의 `name`을 읽어(명세 `Function.prototype.bind`의 `Get(target, "name")`) 앞에 `bound `를 붙이므로, `defineProperty`로 이름을 바꾼 뒤의 `f.bind(null)`은 `"bound z"`입니다. bound function 전반은 [this](/concepts/this-binding)에서 다룹니다. 18번 줄의 `delete f.name`으로 자기 프로퍼티를 지우면 `f`는 자기 `name`이 없어지고 `Object.hasOwn(f, 'name')`이 `false`입니다. 이때 `f.name`은 프로토타입 체인을 따라 `Function.prototype`의 `name`(빈 문자열)을 읽으므로(일반 함수인 `f`의 [[Prototype]]은 `Function.prototype`입니다. [프로토타입 체인](/concepts/prototype-chain)) `""`입니다. 20~21번 줄 `(0, () => {})`로 만든 익명 화살표 함수는 이름은 `""`이지만 자기 `name` 프로퍼티가 있어 `Object.hasOwn`이 `true`입니다.

## 결과와 이유

### 예제 1

출력은 `"decl" "v" "arrow" "later" "cb"`입니다. 함수 선언 `decl`, 초기화식의 `v`와 `arrow`, 왼쪽이 식별자인 대입의 `later`, 매개변수 기본값의 `cb`가 모두 이름을 받았습니다.

### 예제 2

첫 줄은 `"prop" "method"`입니다. 둘째 줄 `"get size" "set size" 1`에서 앞의 둘은 디스크립터에서 꺼낸 getter와 setter의 이름이고, `1`은 `o.size`를 읽어 getter가 실행된 반환값입니다. 셋째 줄 `"item1" "1.5"`는 이름이 소스의 글자 `1.50`이 아니라 키 문자열임을 보입니다.

### 예제 3

첫 줄은 `"" ""`입니다. `o.p`와 `o['q']`의 대입은 왼쪽이 식별자가 아닙니다. 둘째 줄은 인수로 넘긴 함수의 `""`입니다. 셋째 줄 `"paren" "" ""`에서 괄호로 감싼 `paren`만 이름을 받았습니다. `comma`와 `either`는 오른쪽 식이 쉼표 식과 `||` 식이라 함수 정의 그 자체가 아닙니다.

### 예제 4

`"original"`은 `copy`가 새 함수를 만들지 않았기 때문이고, `"inner"`는 이름이 있는 함수 정의가 바인딩 이름을 받지 않았기 때문입니다. `"b" "b"`는 `a`와 `b`가 같은 함수를 가리키고 그 함수가 안쪽 대입에서 `b`라는 이름으로 만들어졌기 때문이며, `"anonymous"`는 Function 생성자가 정한 이름입니다.

### 예제 5

`false false true`는 `writable`, `enumerable`, `configurable`입니다. 5번 줄의 sloppy 대입은 무시되어 `"f"`이고, strict 함수 안의 같은 대입은 `TypeError`입니다. `defineProperty` 뒤에는 `"z" "bound z"`, `delete` 뒤에는 `"" false`이고, 익명 화살표 함수 `anon`은 `"" true`입니다.

### 흔한 오해

<Callout type="misconception" title="name은 함수를 담은 변수의 이름이다">

함수가 어느 변수나 프로퍼티에 있든 그 이름이 `name`이 되는 것이 아닙니다. 익명 함수 정의가 변수 초기화식이나 식별자 대입의 오른쪽 같은 자리에 바로 있을 때 만드는 순간 이름을 받습니다. 예제 4의 `copy`는 `"original"`이고, 예제 3의 `o.p`와 `comma`는 변수나 프로퍼티에 있어도 빈 문자열입니다.

</Callout>

<Callout type="misconception" title="f.name = '새 이름'으로 이름을 바꿀 수 있다">

`name`은 `writable: false`라 대입으로는 바꿀 수 없습니다. 예제 5에서 sloppy mode의 대입은 조용히 무시되고 strict mode의 대입은 `TypeError`입니다. `configurable: true`이므로 `Object.defineProperty`로는 바꿀 수 있고, `bind`는 그 뒤의 `name`을 읽습니다.

</Callout>
