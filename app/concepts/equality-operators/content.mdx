## 동작 원리

자바스크립트에는 두 값이 같은지 묻는 연산자가 네 개 있습니다. 이 연산자들을 이 페이지에서는 동등 연산자라고 부릅니다.

- `===`(일치): 타입이 같고 값도 같으면 `true`입니다.
- `!==`(불일치): `===`의 결과를 뒤집은 것입니다.
- `==`(동등): 타입이 다르면 규칙에 따라 값을 바꾼 뒤 비교합니다.
- `!=`(부동등): `==`의 결과를 뒤집은 것입니다.

### ===는 값을 바꾸지 않고 비교한다

`===`는 두 값의 타입이 다르면 값을 바꾸지 않고 바로 `false`를 돌려줍니다. 타입이 같으면 값을 비교합니다. 문자열은 같은 문자열인지, 불리언은 같은 불리언인지를 봅니다. 숫자에는 예외가 두 가지 있습니다.

- `NaN`은 어떤 숫자와도 같지 않습니다. 자기 자신과도 같지 않으므로 `NaN === NaN`은 `false`입니다.
- `+0`과 `-0`은 같습니다. `0 === -0`은 `true`입니다.

객체는 내용이 아니라 같은 객체인지로 비교합니다. 객체 리터럴을 쓸 때마다 새 객체가 만들어지므로, 내용이 같아 보여도 따로 만든 두 객체는 같지 않고, 같은 객체를 값으로 가진 두 변수만 같습니다. 같은 객체를 값으로 가진다는 것의 의미는 [원시 값과 객체](/concepts/primitives-and-objects) 페이지를 참고하세요.

`===`는 변환 규칙을 몰라도 타입이 같은지, 같다면 값이 같은지만 보면 결과를 예측할 수 있습니다.

### ==는 타입이 다르면 규칙에 따라 바꾼다

문자열이 숫자로 바뀌는 결과(빈 문자열은 0, `'12px'`은 `NaN` 등)는 [암묵적 타입 변환](/concepts/type-coercion) 페이지의 표와 같으므로 여기서 반복하지 않습니다.

### ==는 불리언으로 바꿔 비교하지 않는다

조건식은 값을 불리언으로 바꿔 truthy인지 falsy인지 판정하지만, `==`는 그렇게 하지 않습니다. 한쪽이 불리언이면 그 불리언을 숫자로 바꿉니다. 그래서 `'0'`은 조건식에서는 truthy지만 `'0' == false`는 `true`입니다. `false`가 0이 되고, 이어서 문자열 `'0'`이 숫자 0이 되어 `0 == 0`이기 때문입니다. 반대로 `'true' == true`는 `false`입니다. `true`가 1이 되고, 문자열 `'true'`는 숫자로 읽을 수 없어 `NaN`이 되므로 `1 == NaN`이 되기 때문입니다.

### null과 undefined

`==`는 `null`과 `undefined`를 다른 값으로 바꾸지 않습니다. 둘이 서로 짝일 때만 `true`이고, 그 밖의 값과 비교하면 결국 규칙 ⑤에서 `false`가 됩니다(상대가 불리언이면 규칙 ③으로 불리언이 먼저 숫자로 바뀐 뒤 규칙 ⑤에 이릅니다). `null == 0`, `null == false`, `undefined == ''`는 모두 `false`입니다. 그래서 `x == null`은 `x`가 `null`이거나 `undefined`일 때만 `true`입니다. 이 식이 예제 7에서 쓰입니다.

### ==는 전이적이지 않다

명세의 Note에 따르면 `==`는 항상 전이적(transitive)이지는 않습니다. `0 == ''`와 `0 == '0'`은 모두 `true`지만 `'' == '0'`은 `false`입니다. 앞의 둘은 문자열이 숫자로 바뀐 비교이고, 마지막은 둘 다 문자열이라 문자열끼리 비교하기 때문입니다.

### NaN과 +0/-0을 확인하는 방법

`NaN`은 `===`로 찾을 수 없으므로 `Number.isNaN(x)`로 확인합니다. `Object.is(a, b)`는 `===`와 달리 `NaN`을 `NaN`과 같다고 보고, `+0`과 `-0`을 다르다고 봅니다. 예제 5에서 확인합니다.

예제 1의 `1 === '1'`은 타입이 달라 값을 바꾸지 않고 `false`입니다. `1 == '1'`은 규칙 ②로 `'1'`이 숫자 1이 되어 `true`입니다. `!=`와 `!==`는 각각 `==`와 `===`의 결과를 뒤집으므로 `1 != '1'`은 `false`, `1 !== '1'`은 `true`입니다.

예제 2의 `0 == ''`는 규칙 ②로 빈 문자열이 숫자 0이 되어 `0 == 0`이므로 `true`입니다. `'0' == ''`는 둘 다 문자열이라 타입이 같으므로 `===`와 같은 방법으로 비교하고, 서로 다른 문자열이라 `false`입니다. `0 === ''`는 타입이 달라 `false`입니다. 시뮬레이터에서는 각 비교가 몇 라운드로 끝나는지 볼 수 있습니다.

예제 3의 `false == '0'`은 먼저 규칙 ③으로 `false`가 숫자 0이 되어 `0 == '0'`을 다시 비교합니다. 이번에는 규칙 ②로 `'0'`이 숫자 0이 되어 `0 == 0`이므로 `true`입니다. `true == 'true'`는 `true`가 1이 되어 `1 == 'true'`가 되고, 문자열 `'true'`는 숫자로 읽을 수 없어 `NaN`이 되므로 `1 == NaN`입니다. 타입이 같은 숫자끼리 `===`와 같은 방법으로 비교하면 `NaN`은 어떤 값과도 같지 않아 `false`입니다.

예제 4의 `null == undefined`는 규칙 ①로 `true`입니다. `null == 0`은 `null`을 다른 값으로 바꾸는 규칙이 없어 규칙 ⑤에서 `false`입니다. `null === undefined`는 타입이 달라 `false`입니다.

예제 5의 `x`는 `NaN`이어서 `x === x`가 `false`입니다. 타입이 같은 `==`도 `===`와 같은 결과를 내므로 `x == x`도 `false`입니다. `Number.isNaN(x)`는 `true`이고, `Object.is(x, NaN)`도 `NaN`을 `NaN`과 같다고 보므로 `true`입니다. `0 === -0`은 `+0`과 `-0`이 같아 `true`지만 `Object.is(0, -0)`은 둘을 구분해 `false`입니다.

예제 6에서 `p`와 `q`는 내용이 같아 보이지만 따로 만든 객체이므로 `p == q`와 `p === q` 모두 `false`입니다. `r`은 `p`와 같은 객체를 값으로 가지므로 `p === r`은 `true`입니다. 둘째 줄의 `p == '[object Object]'`는 객체와 문자열의 비교이므로 규칙 ④로 `p`가 먼저 원시 값 `"[object Object]"`가 되고, 다시 비교하면 같은 문자열이라 `true`입니다. 이 변환의 결과는 [암묵적 타입 변환](/concepts/type-coercion) 페이지의 객체 예제와 같습니다.

예제 7의 `value == null`은 `value`가 `undefined`일 때는 규칙 ①로 `true`, `null`일 때는 같은 타입이라 `true`이고, `0`일 때는 규칙 ⑤로 `false`입니다. 첫째 줄의 `value === null`은 `value`가 `undefined`라서 `false`이고, 둘째 줄의 `value === undefined`는 `value`가 `null`이라서 `false`입니다. `===`는 타입이 다르면 바로 `false`이므로 하나의 식으로 `null`과 `undefined`를 함께 확인할 수 없습니다.

<Callout type="misconception" title="==는 양쪽을 불리언으로 바꿔 비교한다">
  `==`는 값을 불리언으로 바꾸지 않습니다. 한쪽이 불리언이면 그 불리언을 숫자(`true`는 1, `false`는
  0)로 바꿉니다. 그래서 조건식에서 truthy인 <code>{"'0'"}</code>도 <code>{"'0' == false"}</code>는
  `true`고,
  <code>{"'true' == true"}</code>는 `false`입니다. 예제 3에서 확인한 결과입니다.
</Callout>

<Callout type="misconception" title="==로 같은 값끼리는 서로도 같다">
  <code>{"0 == ''"}</code>와 <code>{"0 == '0'"}</code>는 모두 `true`입니다. 그런데 이 둘의 오른쪽
  값끼리 비교한 <code>{"'' == '0'"}</code>의 결과는 `false`입니다. 앞의 둘은 문자열이 숫자 0으로
  바뀐 비교이고, 마지막은 둘 다 문자열이라 바뀌지 않고 문자열끼리 비교하기 때문입니다. 명세도 `==`가
  항상 전이적이지는 않다고 밝힙니다.
</Callout>

<Callout type="misconception" title="null은 0이나 false와 ==로 같다">
  `==`는 `null`과 `undefined`를 다른 값으로 바꾸지 않습니다. 둘이 서로 짝일 때만 `true`고,
  나머지와는 규칙 ⑤에서 `false`입니다. `null == 0`, `null == false`,{' '}
  <code>{"undefined == ''"}</code>는 모두 `false`입니다. `x == null`이 `true`인 경우는 `x`가
  `null`이거나 `undefined`일 때뿐입니다.
</Callout>

<Callout type="misconception" title="NaN은 === NaN으로 찾을 수 있다">
  `NaN`은 자기 자신을 포함해 어떤 값과도 `===`로 같지 않습니다. 예제 5에서 `x === x`가
  `false`였습니다. `==`도 같은 결과입니다. `NaN`인지 확인하려면 `Number.isNaN(x)`를 쓰고,
  `Object.is(x, NaN)`도 `true`를 돌려줍니다.
</Callout>

<Callout type="misconception" title="내용이 같은 두 객체는 ==로 같다">
  객체끼리의 `==`와 `===`는 내용이 아니라 같은 객체인지를 비교합니다. 예제 6에서 `p`와 `q`는 둘 다{' '}
  <code>{'{ n: 1 }'}</code>로 내용이 같아 보이지만 따로 만든 객체라 `p == q`는 `false`입니다. 같은
  객체를 값으로 가진 `p`와 `r`만 `p === r`이 `true`입니다.
</Callout>
