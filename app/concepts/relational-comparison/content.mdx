import { pairs } from './pairs'

`null >= 0`은 `true`인데 `null > 0`은 `false`이고 `null == 0`도 `false`입니다. 0보다 크지도 0과 같지도 않은데 "0보다 크거나 같다"가 참이라니 모순처럼 보입니다. 이 페이지는 관계 연산자 가운데 크기를 비교하는 넷(`<`, `>`, `<=`, `>=`)을 ECMAScript 명세가 어떻게 계산하는지 따라가며 null·undefined·NaN 비교, `<=`와 `>=`의 정의, 범위 검사의 함정, 피연산자를 원시 값으로 바꾸는 순서를 실행 결과로 확인합니다. `null == 0`이 `false`인 이유(`==`는 null을 숫자로 바꾸지 않습니다)는 [동등 비교](/concepts/equality-operators)에서, 두 값이 모두 문자열일 때의 비교는 [암묵적 타입 변환](/concepts/type-coercion)의 예제 5에서 다룹니다.

## 동작 원리

### `<`는 문자열끼리가 아니면 숫자로 바꿔 비교하고, 비교할 수 없으면 결과가 없다

명세에서 `a < b`는 두 피연산자 식을 왼쪽, 오른쪽 순서로 평가해 값을 얻은 뒤 추상 연산 IsLessThan(왼쪽 값, 오른쪽 값, true)을 부릅니다. 결과가 `undefined`이면 `false`를 돌려주고, 아니면 그 결과를 돌려줍니다. IsLessThan은 `true`, `false`, `undefined` 셋 중 하나를 돌려주며, 명세는 `undefined`를 피연산자를 같은 숫자 타입의 비교 가능한 값으로 바꿀 수 없다는 뜻이라고 설명합니다. 이 페이지에서 "결과가 없다"는 IsLessThan이 `undefined`를 돌려준다는 뜻이고, 그때도 연산자 식의 값은 `undefined`가 아니라 `false`입니다.

IsLessThan은 먼저 두 값을 원시 값으로 바꿉니다(원시 값은 그대로입니다). 그 결과가 둘 다 문자열이면 숫자로 바꾸지 않고 문자열의 코드 유닛을 앞에서부터 비교하고, 그 밖의 경우에는 두 값을 각각 숫자로 바꾼 뒤 숫자끼리 비교합니다(BigInt가 끼는 비교는 [BigInt](/concepts/bigint)에서 다룹니다). 바뀌는 값은 `null`이 `0`, `undefined`가 `NaN`, 빈 문자열과 공백만 있는 문자열이 `0`, 숫자로 읽을 수 없는 문자열이 `NaN`, `false`가 `0`입니다([암묵적 타입 변환](/concepts/type-coercion)의 표와 그 아래 설명). 숫자끼리의 비교(Number::lessThan)는 한쪽이라도 `NaN`이면 `undefined`를 돌려줍니다. 그래서 `NaN`이 끼면 `<`와 `>`는 항상 `false`입니다.

### `<=`와 `>=`는 `<`·`>`에 `==`를 더한 것도, 부정도 아니다

명세는 네 연산자를 모두 IsLessThan으로 정의합니다. `>`는 IsLessThan(오른쪽 값, 왼쪽 값, false)을 부르고 결과가 `undefined`이면 `false`입니다. `<=`는 같은 IsLessThan(오른쪽 값, 왼쪽 값, false)의 결과가 `true`이거나 `undefined`이면 `false`, 아니면 `true`입니다. `>=`는 IsLessThan(왼쪽 값, 오른쪽 값, true)의 결과가 `true`이거나 `undefined`이면 `false`, 아니면 `true`입니다. 곧 `>=`는 IsLessThan이 `false`를 돌려줄 때만 `true`이고, `<=`도 자리를 바꾼 IsLessThan이 `false`를 돌려줄 때만 `true`입니다.

여기서 두 가지가 따라옵니다. 하나는 `a >= b`가 `a > b || a == b`의 줄임이 아니라는 것입니다. `>=`의 정의에는 `==`가 들어 있지 않고, `null`은 `0`으로 바뀌어 `>=`에서는 `0 >= 0`이 되지만 `==`는 `null`을 바꾸지 않습니다. 다른 하나는 `a >= b`가 `!(a < b)`도 아니라는 것입니다. `NaN`이 끼면 IsLessThan이 `undefined`를 돌려주므로 `a < b`는 `false`지만 `a >= b`도 `false`입니다.

`>`와 `<=`가 왼쪽과 오른쪽 값의 자리를 바꿔 IsLessThan에 넘기는 것은 명세의 정의입니다. 자리를 바꾼다는 것은 명세가 정의를 적는 방식이어서 실행 결과로는 구별되지 않습니다. 변환 순서를 leftFirst로 맞추므로, 자리를 바꾸지 않고 `a > b`를 직접 계산하는 모델도 같은 결과를 내기 때문입니다.

### 범위 검사는 타입을 걸러 주지 않는다

`v >= 0 && v <= 10`은 `v`가 숫자인지 확인하지 않습니다. `v`가 숫자가 아니어도 비교가 값을 숫자로 바꿉니다. `null`, 빈 문자열, 공백 문자열, `false`는 모두 `0`으로 바뀌어 통과합니다. `undefined`와 `'abc'`는 `NaN`이 되어 첫 비교 `v >= 0`부터 `false`이고, `&&`는 오른쪽 `v <= 10`을 평가하지 않고 `false`를 돌려주므로 걸러집니다. 걸러지는 기준은 타입이 아니라 숫자로 바꾼 결과가 `0` 이상 `10` 이하에 드느냐이고, `NaN`은 어떤 관계 비교에서도 결과가 없어 걸러집니다. `&&`는 왼쪽 값이 falsy이면 오른쪽을 평가하지 않고 왼쪽 값을 돌려줍니다([단축 평가](/concepts/short-circuit-evaluation)). 이 검사에서는 두 식이 모두 불리언이라 결과가 불리언 그대로입니다.

### 피연산자를 모두 평가한 뒤 왼쪽부터 바꾼다

관계 연산자는 두 피연산자 식을 먼저 모두 평가한 다음에야 IsLessThan이 값을 바꿉니다. 피연산자가 `valueOf`를 가진 객체이면 IsLessThan이 그 객체를 원시 값으로 바꿀 때(number 힌트) `valueOf`가 불립니다([객체를 원시 값으로](/concepts/to-primitive)). IsLessThan의 마지막 인수 leftFirst가 `false`이면 첫째 인수가 오른쪽 피연산자의 값이어서, 명세는 왼쪽에서 오른쪽으로 평가한다는 규칙을 지키려고 변환 순서를 뒤집는다고 NOTE에 적습니다. 그래서 `>`와 `<=`에서도 왼쪽 피연산자의 값을 먼저 원시 값으로 바꿉니다. 두 값이 모두 원시 값이 된 뒤에야 둘 다 문자열인지 보고, 아니면 그때 숫자로 바꿉니다. 곧 "왼쪽 원시 값 → 오른쪽 원시 값 → 숫자로" 순서이고, `valueOf`가 문자열을 돌려주면 숫자 비교가 아니라 문자열 비교가 될 수도 있습니다. 예제 5의 `valueOf`는 숫자를 돌려주므로 원시 값으로 바꾼 결과가 곧 숫자입니다. 예제 5가 보이는 것은 이 가운데 두 피연산자가 모두 평가된 뒤에 왼쪽 값부터 원시 값으로 바뀐다는 결과뿐이고, 인수 자리를 바꾸는 단계는 보이지 않습니다.

## 결과와 이유

### 예제 1

1번 줄에서 `null > 0`은 `false`, `null == 0`은 `false`, `null >= 0`은 `true`입니다. `null`이 `0`으로 바뀌므로 `0 > 0`은 `false`이고 `0 >= 0`은 `true`입니다. `==`는 `null`을 숫자로 바꾸지 않아 `null == 0`은 `false`입니다([동등 비교](/concepts/equality-operators)). 2번 줄의 `null < 1`과 `null <= 0`은 `0 < 1`과 `0 <= 0`이라 `true`이고, `null == false`는 `false`가 `0`으로 바뀌어 `null == 0`과 같은 비교가 되지만 `null`은 바뀌지 않아 `false`입니다.

이 예제는 세 가지 틀린 모델을 가려냅니다. `null`이 낀 관계 비교를 모두 `false`로 보는 모델은 1번 줄이 `false false false`입니다. `<=`와 `>=`를 `<`·`>`이거나 `==`로 보는 모델은 1번 줄이 `false false false`, 2번 줄이 `true false false`입니다. `==`도 `null`을 `0`으로 바꾼다고 보는 모델은 1번 줄의 `null == 0`이 `true`입니다.

### 예제 2

1번 줄의 `undefined`는 `NaN`이 되어 네 비교가 모두 `false`이고, 2번 줄도 `NaN`이 끼어 `NaN <= NaN`을 포함한 네 비교가 모두 `false`입니다. `NaN`은 자기 자신보다 크거나 같은지도, 작거나 같은지도 정해지지 않습니다. 예제 1의 `null <= 0`은 `true`였고 이 예제의 `undefined <= 0`은 `false`입니다. 같은 `<= 0` 비교인데 `null`은 `0`으로, `undefined`는 `NaN`으로 바뀌기 때문입니다.

`>=`를 `<`의 부정으로, `<=`를 `>`의 부정으로 보는 모델은 이 예제에서 `>=`와 `<=` 칸이 `true`가 됩니다. `undefined`도 `0`으로 바뀐다고 보는 모델은 1번 줄의 `>=`와 `<=`가 `true`입니다. `NaN`이 자기 자신과 같다고 보는 모델은 2번 줄 마지막 칸이 `true`입니다.

### 예제 3

예제 3은 `<=`와 `>=`의 두 가지 후보 정의를 같은 줄에 놓습니다. 줄마다 첫째 값은 실제 `<=`(1번 줄)나 `>=`(2번 줄)입니다. 둘째 값은 `a < b || a == b`(1번 줄)와 `c > d || c == d`(2번 줄)로 계산한 값이고, 셋째 값은 반대 연산자의 부정 `!(a > b)`(1번 줄)와 `!(c < d)`(2번 줄)입니다. 어느 쪽이 정의라면 모든 줄에서 첫째 값과 같아야 합니다.

1번 줄(a는 `null`, b는 `0`)은 `true false true`입니다. 둘째 값이 첫째 값과 달라서 `<=`는 `<`이거나 `==`가 아닙니다. 2번 줄(c는 `NaN`, d는 `1`)은 `false false true`입니다. 셋째 값이 첫째 값과 달라서 `>=`는 `<`의 부정이 아닙니다. 두 후보는 각각 한 줄에서 어긋나므로 어느 쪽도 두 연산자 모두의 정의가 될 수 없습니다. 다만 1번 줄은 `<=`만, 2번 줄은 `>=`만 대조하므로, 두 후보를 섞은 모델(`<=`는 `>`의 부정, `>=`는 `>`이거나 `==`)은 이 예제의 두 줄을 그대로 맞힙니다. 이 섞인 모델은 예제 1의 `null >= 0`(섞인 모델은 `false`)과 예제 2의 `undefined <= 0`(섞인 모델은 `true`)이 가려냅니다. 예제 1~3을 모두 설명하는 것은 명세의 정의, 곧 IsLessThan의 결과가 `true`나 `undefined`이면 `false`라는 정의입니다. 다만 이 예제는 결과만 비교하므로, `<=`는 자리를 바꾼 IsLessThan(오른쪽 값, 왼쪽 값)으로, `>=`는 자리를 바꾸지 않은 IsLessThan(왼쪽 값, 오른쪽 값)으로 계산된다는 것은 명세 정의로 읽어야 합니다.

### 예제 4

`inRange`는 `v >= 0 && v <= 10`을 돌려줍니다. 1번 줄은 `inRange(null)`이 `true`, `inRange(undefined)`가 `false`, 빈 문자열과 공백 문자열이 `true`입니다. 2번 줄은 `'5'`가 `true`, `'abc'`가 `false`, `false`가 `true`, `11`이 `false`입니다. 통과한 값은 모두 숫자로 바뀐 결과가 `0` 이상 `10` 이하입니다. 걸러진 `undefined`와 `'abc'`는 `NaN`이 되어 비교 결과가 없었고(`v <= 10`은 평가되지 않았습니다), `11`은 숫자 비교에서 `10` 이하가 아니었습니다.

`null`이 낀 비교를 `false`로 보는 모델은 1번 줄 첫 칸이 `false`입니다. 값을 truthy면 `1`, falsy면 `0`으로 본다면 `undefined`가 `0`이 되어 1번 줄 둘째 칸이, `'abc'`가 `1`이 되어 2번 줄 둘째 칸이 `true`입니다. 문자열과 숫자는 비교하지 않는다고 보는 모델은 문자열이 낀 칸이 모두 `false`입니다. 정리하면 이 검사는 `null`, 빈 문자열, 공백 문자열, `false`를 통과시킵니다. 숫자만 받으려면 `typeof v === 'number'`처럼 타입을 따로 확인해야 합니다([typeof 연산자](/concepts/typeof-operator)).

### 예제 5

두 줄의 출력은 `abAB`로 같습니다. 소문자 `a`, `b`는 `val`이 불린 순서(피연산자 평가)이고 대문자 `A`, `B`는 `valueOf`가 불린 순서(원시 값으로 바뀜)입니다. 두 피연산자가 먼저 평가되어 `ab`가 기록되고, 그다음 왼쪽 값부터 원시 값으로 바뀌어 `AB`가 기록됩니다. `>`(1번 줄)와 `<=`(2번 줄) 모두 같은 순서입니다. 평가하자마자 바꾸는 모델은 `aAbB`가 되고, `>`와 `<=`에서 오른쪽 값부터 바꾸는 모델은 `abBA`가 됩니다.

이 예제가 보이는 것은 두 피연산자가 모두 평가된 뒤 왼쪽 값부터 원시 값으로 바뀐다는 결과입니다. `>`와 `<=`가 자리를 바꿔 IsLessThan을 부른다는 것 자체는 이 출력으로 구별할 수 없습니다. `<`와 `>=`는 이 예제에 없으며, 이들의 변환 순서는 명세의 정의에서 옵니다.

표에서 새로 얻는 정보는 주로 마지막 행과 `==` 열입니다. `null`과 `undefined`는 `==`가 `true`이지만 관계 비교는 모두 `false`입니다. `==`는 둘을 서로 같은 값으로 보고, 관계 비교는 `null`을 `0`으로, `undefined`를 `NaN`으로 바꿔 비교 결과가 없기 때문입니다. `null`과 `0` 행에서는 `<=`와 `>=`가 `true`인데 `==`가 `false`입니다. 빈 문자열, 공백 문자열, `false`와 `0` 행은 `<=`, `>=`, `==`가 모두 `true`이고, `NaN`과 `1` 행, `'abc'`와 `1` 행은 `NaN`이 끼어 `==`까지 모두 `false`입니다.

### 흔한 오해

<Callout type="misconception" title="a >= b는 a > b이거나 a == b다">

`>=`는 `>`와 `==`로 정의되지 않습니다. 예제 1에서 `null >= 0`은 `true`인데 `null > 0`도 `null == 0`도 `false`입니다. `>=`는 IsLessThan이 `false`를 돌려줄 때만 `true`이고 `==`와 아무 관련이 없습니다. 반대로 `a < b`의 부정으로 읽어도 틀립니다. 예제 2와 3에서 `NaN >= 1`은 `false`인데 `NaN < 1`도 `false`입니다.

</Callout>

<Callout type="misconception" title="null은 falsy라서 비교에서 0이 된다">

`null`이 `0`이 되는 것은 falsy라서가 아니라 숫자로 바꾸는 규칙(ToNumber)이 `null`을 `0`으로 정하기 때문입니다. `undefined`도 falsy지만 숫자로 바꾸면 `NaN`이어서 예제 2의 `undefined >= 0`은 `false`이고 예제 4의 `inRange(undefined)`도 `false`입니다. 반대로 truthy인 `'abc'`가 걸러지는 것은 `NaN`이 되기 때문이고, truthy인 `'5'`는 `1`이 아니라 `5`가 됩니다.

</Callout>
