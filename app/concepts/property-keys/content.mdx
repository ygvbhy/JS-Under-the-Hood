## 동작 원리

객체는 프로퍼티(property)의 모음이고, 각 프로퍼티는 프로퍼티 키(property key)로 구분합니다. 프로퍼티 키는 문자열 또는 심벌인데, 이 페이지는 문자열 키만 다룹니다(심벌은 별도 개념입니다). 이 페이지의 질문은 "점 표기와 대괄호 표기가 각각 어떤 값을 프로퍼티 키로 쓰는가"입니다.

### 점 표기: 점 뒤의 이름이 그대로 키

`obj.name`처럼 점 뒤에 이름을 쓰면 그 이름이 그대로 프로퍼티 키(`"name"`)가 됩니다. 변수 `name`이 있어도 그 값은 쓰이지 않습니다. 점 뒤에는 식별자 이름(IdentifierName)만 쓸 수 있습니다.

- `class` 같은 예약어도 식별자 이름이므로 `product.class`처럼 쓸 수 있습니다.
- `obj.1`처럼 숫자로 시작하는 이름은 식별자 이름이 아니라서, 코드를 실행하기 전에 SyntaxError입니다.
- `product.unit-price`는 `unit-price`라는 키 하나가 아니라, 프로퍼티 `product.unit`에서 변수 `price`를 뺀 식 `product.unit - price`로 해석됩니다.

### 대괄호 표기: 식의 값을 문자열로 바꿔 키로

`obj[식]`은 대괄호 안의 식을 평가한 값을 문자열로 바꿔 프로퍼티 키로 씁니다(명세의 ToPropertyKey). 문자열로 바꾸는 규칙은 [암묵적 타입 변환](/concepts/type-coercion) 페이지에서 다룬 것과 같습니다.

- 숫자 `1`은 `"1"`이 됩니다. `1.0`은 숫자 `1`과 같은 값이므로 역시 `"1"`입니다.
- `true`는 `"true"`, `null`은 `"null"`이 됩니다.
- 일반 객체는 `"[object Object]"`가 됩니다. 이 페이지는 이 결과만 보여 줍니다.
- 이미 문자열인 값은 그대로 키가 됩니다. `'01'`은 `"01"`이므로 숫자 `1`의 키 `"1"`과 다릅니다.
- `0.1 + 0.2`는 숫자 `0.30000000000000004`이므로 키는 `"0.30000000000000004"`입니다([숫자 타입](/concepts/number-type) 페이지의 부동소수점 오차 때문입니다).

그래서 `obj.key`와 `obj[key]`는 다릅니다. 점 표기는 이름 `key`를 그대로 키로 쓰고, 대괄호 표기는 변수 `key`의 값을 키로 씁니다.

### 객체 리터럴의 키도 같은 규칙

객체 리터럴 `{ ... }`에서도 키는 문자열이 됩니다. 이름과 문자열 리터럴은 그대로, 숫자 리터럴은 문자열로 바뀝니다(`1e3`은 `"1000"`). `{ [식]: 값 }`처럼 대괄호로 감싼 계산된 프로퍼티 이름(computed property name)은 식의 값을 문자열로 바꿔 키로 씁니다. 대괄호 표기와 같은 규칙입니다.

### 읽기, 추가, 값 바꾸기, 지우기

- 읽기: 그 키의 프로퍼티가 있으면 값을, 없으면 `undefined`를 돌려줍니다. 오류가 아닙니다. 객체에 없을 때 프로토타입까지 찾는 과정은 별도 개념에서 다룹니다.
- 읽는 대상이 `undefined`나 `null`이면 TypeError입니다. `obj.missing`은 `undefined`지만 `obj.missing.x`는 `undefined`의 프로퍼티를 읽으므로 TypeError입니다. 옵셔널 체이닝 `?.`로 이 오류를 피하는 방법은 [단축 평가](/concepts/short-circuit-evaluation) 페이지에서 볼 수 있습니다.
- 대입 `obj[키] = 값`: 그 키의 프로퍼티가 없으면 프로퍼티를 추가하고, 있으면 값을 바꿉니다.
- `delete obj[키]`: 프로퍼티를 지우고 `true`를 돌려줍니다. 없는 키를 지우려 해도 `true`입니다. 그래서 `true`는 "그 프로퍼티가 있었다"는 뜻이 아닙니다.

예제 1에서 `scores[1] = '금'`의 대괄호 안 값은 숫자 `1`이고, 이것이 문자열 `"1"`로 바뀌어 프로퍼티 키가 됩니다. 그래서 `scores['1']`로 읽으면 `금`입니다. `scores['2']`는 문자열이 그대로 키이고, 숫자 `2`로 읽어도 같은 키 `"2"`이므로 `은`입니다. <code>{"scores['1'] = '동'"}</code>은 키 `"1"`의 프로퍼티가 이미 있어서 새로 추가하지 않고 값을 바꿉니다. 객체에는 키 `"1"`과 `"2"`, 두 프로퍼티만 있습니다.

예제 2의 `user.name`은 이름 `name`이 그대로 키이고, `user['name']`은 문자열 `'name'`이 키입니다. `user[key]`는 변수 `key`를 평가한 값 `'name'`이 키입니다. 마지막 `user.key`는 변수 `key`를 평가하지 않고 이름 `key`가 그대로 키이므로, 객체 리터럴에서 키 `key`로 넣어 둔 `열쇠`를 읽습니다.

예제 3의 첫 줄에서 `box`에는 키 `"b"`가 없으므로 `box.b`는 `undefined`입니다. 오류는 나지 않습니다. 이어서 `box.b = 2`는 키 `"b"`의 프로퍼티를 추가하고, `box.a = 10`은 이미 있는 키 `"a"`의 값을 바꿉니다. `delete box.a`는 프로퍼티를 지우고 `true`를 돌려주며, 지운 뒤 `box.a`는 `undefined`입니다. `delete box.c`는 지울 프로퍼티가 처음부터 없는데도 `true`를 돌려줍니다. 마지막 `JSON.stringify(box)`에는 `b`만 남습니다.

예제 4에서 `{ field: '빨강' }`의 `field`는 이름이라 변수 `field`의 값과 상관없이 키가 `"field"`입니다. `{ [field]: '빨강' }`은 대괄호 안의 식을 평가하므로 변수 `field`의 값 `'color'`가 키입니다. `['size' + n]`은 식 `'size' + n`의 값 `'size2'`가 키입니다.

예제 5의 리터럴 `{ 1: '하나', 1e3: '천' }`에서 숫자 `1`은 키 `"1"`, 숫자 `1e3`은 값이 1000이므로 키 `"1000"`입니다. `t[1.0]`의 `1.0`은 숫자 `1`과 같은 값이라 키 `"1"`로 읽어 `하나`를, `t['1000']`은 `천`을 읽습니다. 반면 `t['01']`과 `t['1.0']`은 이미 문자열이므로 그대로 키 `"01"`, `"1.0"`이 되고, 이런 키의 프로퍼티는 없어서 `undefined undefined`입니다. `t[0.1 + 0.2]`는 부동소수점 오차가 있는 값 `0.30000000000000004`가 문자열로 바뀐 키로 프로퍼티를 추가합니다.

예제 6에서 `m[true]`는 키 `"true"`, `m[null]`은 키 `"null"`입니다. `m[{}]`의 빈 객체는 일반 객체라 키가 `"[object Object]"`가 됩니다. `m[{ a: 1 }]`은 `m[{}]`와 서로 다른 객체이지만 문자열로 바뀐 결과가 같은 `"[object Object]"`이므로 같은 프로퍼티를 읽어 `빈 객체`가 출력됩니다. 객체가 어떤 과정을 거쳐 이 문자열이 되는지는 이 페이지에서 다루지 않습니다.

예제 7에서 `product['unit-price']`는 문자열이 키이므로 `1000`입니다. `product.unit-price`는 점 뒤의 식별자 이름이 `unit`에서 끝나고 `-`는 뺄셈 연산자입니다. 그래서 `product.unit`(키 `"unit"`의 프로퍼티는 없으므로 `undefined`)에서 변수 `price`의 값 3을 뺀 `undefined - 3`이고, `undefined`를 숫자로 바꾸면 `NaN`이므로 결과도 `NaN`입니다. `product.class`는 예약어도 식별자 이름이라 점 뒤에 쓸 수 있어 `A`입니다. 이름이 숫자로 시작하는 `obj.1`은 식별자 이름이 아니라서 코드를 실행하기 전에 SyntaxError입니다.

<Callout type="misconception" title="obj[1]과 obj['1']은 다른 프로퍼티다">
  대괄호 안의 값은 문자열로 바뀌어 프로퍼티 키가 되므로, 숫자 `1`과 문자열 `'1'`은 같은 키
  `"1"`입니다. 예제 1에서 <code>{"scores['1'] = '동'"}</code>은 새 프로퍼티를 만들지 않고
  `scores[1]`로 넣은 프로퍼티의 값을 바꿨습니다.
</Callout>

<Callout type="misconception" title="obj.key는 변수 key의 값을 키로 쓴다">
  점 표기는 점 뒤의 이름이 그대로 키입니다. 예제 2에서 변수 `key`의 값이 `'name'`이어도 `user.key`는
  키 `"key"`의 프로퍼티인 `열쇠`를 읽었고, 변수의 값을 키로 쓴 것은 `user[key]`였습니다.
</Callout>

<Callout type="misconception" title="없는 프로퍼티를 읽으면 오류가 난다">
  없는 키를 읽는 것은 오류가 아니고 `undefined`를 돌려줍니다. 예제 3의 `box.b`가 그랬습니다. 오류가
  나는 경우는 읽는 대상 자체가 `undefined`나 `null`일 때입니다. `box.b`가 `undefined`일 때
  `box.b.x`를 읽으려 하면 `undefined`의 프로퍼티를 읽는 것이라 TypeError입니다.
</Callout>

<Callout type="misconception" title="delete가 true를 돌려주면 그 프로퍼티가 있었다는 뜻이다">
  예제 3에서 `delete box.c`는 `c`가 처음부터 없는데도 `true`를 돌려줬습니다. 이 `true`로는 지우기
  전에 프로퍼티가 있었는지 알 수 없습니다.
</Callout>

<Callout type="misconception" title="객체를 키로 쓰면 객체마다 다른 키가 된다">
  대괄호 안의 값은 문자열로 바뀌어 키가 되므로, 일반 객체는 어느 것이든 같은 키{' '}
  <code>{'"[object Object]"'}</code>가 됩니다. 예제 6에서 <code>{'m[{}]'}</code>로 넣은 값을 서로
  다른 객체 <code>{'{ a: 1 }'}</code>로 읽었는데도 같은 `빈 객체`가 나왔습니다.
</Callout>
