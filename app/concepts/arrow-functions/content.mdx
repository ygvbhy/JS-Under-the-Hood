## 동작 원리

`function` 키워드로 만든 일반 함수, 객체 리터럴의 메서드 축약(method shorthand), 화살표 함수(arrow function)는 모두 `typeof`가 `'function'`입니다. 그렇다면 셋은 같은 함수일까요? 호출할 수 있다는 점은 같지만, `new`로 부를 수 있는지, `prototype` 프로퍼티가 있는지, `this`·`arguments`·`new.target`·`super`를 어떻게 다루는지가 다릅니다. 이 페이지는 화살표 함수 문법, 생성자가 아닌 까닭, `arguments` 객체, 화살표 함수가 바깥에서 찾는 이름들, 메서드 축약과 `super`, 중복 매개변수, rest 파라미터(rest parameter)를 예제 여섯 개로 살펴보고, 마지막에 비교표로 정리합니다. 함수 호출은 [함수 호출](/concepts/function-calls), `this`는 [this](/concepts/this-binding), `new`는 [new 연산자](/concepts/new-operator), `super`는 [클래스 상속과 super](/concepts/class-inheritance), 이름을 바깥 환경에서 찾는 과정은 [스코프 체인](/concepts/scope-chain)에서 본 것을 전제합니다. [매개변수 기본값](/concepts/default-parameters)은 별도 페이지에서 다루므로 여기서 다루지 않습니다.

### 화살표 함수 문법

예제 1의 1번 줄처럼 매개변수가 식별자 하나뿐이면 괄호를 생략할 수 있습니다. rest 파라미터, 기본값, 구조 분해가 하나라도 있으면 괄호가 필요해서 `...a => a`는 SyntaxError입니다. 화살표 뒤가 `{`로 시작하지 않으면 식 본문(expression body)이고, 그 식의 값이 함수의 반환값입니다. 그래서 2번 줄의 `add(2, 3)`은 `5`를 돌려줍니다. 화살표 뒤가 `{`로 시작하면 이것은 식이 아니라 일반 함수와 같은 함수 본문(블록 본문)입니다. 3번 줄의 `noReturn`은 본문에서 `a + b`를 계산만 하고 `return`이 없으므로 `undefined`를 돌려주고, 4번 줄의 `withReturn`은 `return`이 있어 `5`를 돌려줍니다.

6번 줄은 흔한 함정입니다. `() => { value: 1 }`에서 `{`는 객체 리터럴이 아니라 본문의 시작입니다. `value:`는 레이블이고 `1`은 그냥 식문장이라 `return`이 없는 함수가 되어, `label()`은 `undefined`입니다. 객체를 바로 돌려주려면 7번 줄처럼 `({ value: 1 })`로 괄호를 씌워 `{`가 식의 시작이 되게 합니다.

### 생성자가 아니다

예제 2의 4번 줄에서 일반 함수 `normal`, 메서드 축약으로 만든 `obj.short`, 화살표 함수 `arrow`의 `typeof`는 모두 `'function'`입니다. 셋 다 `[[Call]]` 내부 메서드를 가졌기 때문입니다. 하지만 `new`로 부를 수 있는지는 다릅니다. `new`는 피연산자가 생성자(`[[Construct]]`가 있는 객체)가 아니면 TypeError를 만듭니다(명세의 EvaluateNew). 그런데 명세에서 함수 객체를 만드는 `OrdinaryFunctionCreate`는 `[[Call]]`만 있는 함수를 만들 뿐이고, `[[Construct]]`는 `MakeConstructor`를 따로 불러야 붙습니다. `MakeConstructor`는 `[[Construct]]`를 붙이면서 `prototype` 프로퍼티도 함께 만듭니다. `function` 식과 선언은 `MakeConstructor`를 부르므로 `new`로 부를 수 있고 `prototype`이 있습니다. 메서드 축약(`DefineMethod`)과 화살표 함수(`InstantiateArrowFunctionExpression`)는 `OrdinaryFunctionCreate`만 부르고 `MakeConstructor`는 부르지 않습니다. 그래서 5번 줄에서 `new normal()`과 `function` 식으로 만든 `new obj.old()`는 객체를 만들지만, 6번 줄의 `new obj.short()`와 7번 줄의 `new arrow()`는 `TypeError`입니다. 8번 줄의 `prototype` 프로퍼티 유무도 같은 원인으로 갈립니다. `normal`은 `true`이고 `obj.short`와 `arrow`는 `false`입니다.

### arguments 객체

화살표 함수가 아닌 함수(일반 함수와 메서드 축약)는 호출될 때 `arguments` 객체를 만듭니다(명세의 FunctionDeclarationInstantiation. 매개변수나 함수 안 선언의 이름이 `arguments`인 경우 같은 예외는 여기서 다루지 않습니다). 선언한 매개변수 개수와 관계없이 호출 때 넘긴 인수를 모두 담습니다. 예제 3의 1~3번 줄 `count`는 매개변수가 없는데도 10번 줄에서 `count(1, 2, 3)`의 `arguments.length`가 `3`이고, 인수 없이 부른 `count()`는 `0`입니다. 4~6번 줄 `second`는 매개변수가 `a` 하나뿐이지만 11번 줄의 `arguments[1]`로 두 번째 인수 `'y'`를 읽습니다.

`arguments`는 배열이 아닙니다. 명세는 `arguments`를 `length`와 인덱스 프로퍼티를 가진, 배열 객체가 아닌 객체로 만들고 `[[Prototype]]`을 `Object.prototype`으로 둡니다. 그래서 7~9번 줄의 `kind`가 12번 줄에서 보이듯 `Array.isArray(arguments)`는 `false`이고, 프로토타입 체인에 `Array.prototype`이 없어 `typeof arguments.join`도 `'undefined'`입니다. 배열 메서드가 없을 뿐, `length`와 인덱스 프로퍼티가 있으므로 진짜 배열로 바꾸는 방법은 있습니다. 배열 메서드를 빌려 쓰는 방법과 이터러블·스프레드를 쓰는 방법인데, 앞의 것은 배열로 바꾸는 용도로는 이 사이트에서 아직 다루지 않은 별도 개념이고 이터러블과 스프레드는 [이터러블과 for...of](/concepts/iterable-for-of)와 [스프레드와 디스트럭처링](/concepts/spread-destructuring)에서 다룹니다. 이 페이지는 sloppy mode에서 `arguments[0]`과 매개변수가 연동되는 동작(mapped arguments)은 다루지 않습니다. 예제 3의 `arguments`는 sloppy mode의 단순한 매개변수 목록이라 명세상 mapped 객체이지만, 배열이 아니고 `[[Prototype]]`이 `Object.prototype`인 점은 같습니다.

### 화살표 함수가 바깥에서 찾는 것

화살표 함수는 자기 `this`, `arguments`, `super`, `new.target` 바인딩을 만들지 않습니다. 명세는 화살표 함수가 이 이름들의 지역 바인딩을 정의하지 않고, 이 이름들의 참조는 렉시컬하게 바깥을 둘러싼 환경의 바인딩으로 해석된다고 정합니다. 화살표 함수는 만들어질 때 그것을 평가하던 실행 컨텍스트의 렉시컬 환경(만들어진 곳)을 `[[Environment]]`로 가지므로, 안에서 못 찾은 이름은 일반 식별자처럼 바깥으로 올라가며 찾습니다([스코프 체인](/concepts/scope-chain)).

`this`와 `new.target`, `super`는 이 규칙이 환경 레코드에서 이렇게 나타납니다. 화살표 함수의 함수 환경 레코드는 `this` 바인딩을 갖지 않는 상태(lexical)라서 `HasThisBinding()`이 `false`입니다. `this`를 평가하거나 `new.target`을 읽을 때 명세는 GetThisEnvironment로 바깥으로 올라가며 처음 `this` 바인딩이 있는 환경을 찾고, 거기서 값을 읽습니다. `super`도 같습니다. 명세는 `super.x`를 평가할 때도 GetThisEnvironment로 환경을 찾으므로, 화살표 함수 안의 `super`는 바깥 메서드의 함수 환경에서 그 메서드의 `[[HomeObject]]`의 `[[Prototype]]`을 출발점으로 씁니다. `arguments`는 `this`·`new.target`·`super`와 달리 GetThisEnvironment를 거치지 않습니다. 일반 함수의 `arguments`도 FunctionDeclarationInstantiation이 함수 환경에 만든 보통의 바인딩이고, 이름을 찾는 과정은 다른 식별자와 같습니다. 명세는 `[[ThisMode]]`가 lexical인 함수에는 이 바인딩을 만들지 않는다고 정하므로, 화살표 함수 안의 `arguments`는 식별자 해석이 그대로 스코프 체인을 따라 바깥 함수의 `arguments` 바인딩에 닿습니다.

예제 4에서 확인합니다. 1번 줄의 `Box`는 3번 줄에서 화살표 함수를 `this.read`에 담고, 4번 줄에서는 같은 식을 돌려주는 일반 함수를 `this.plain`에 담습니다. 6번 줄의 `new Box('A', 'extra')`로 `Box`가 호출될 때 `this`는 새 객체(`box`), `arguments.length`는 `2`, `new.target`은 `Box`입니다. 8번 줄의 `box.read(1, 2, 3)`은 `A 2 true`를 출력합니다. 인수를 세 개 넘겼는데도 `arguments.length`가 `2`인 것은, 화살표 함수 안의 `arguments`가 `read`의 인수가 아니라 `Box` 호출의 `arguments`를 가리키기 때문입니다. 7번 줄에서 `read`와 `plain`을 다른 객체 `other`에 옮겨 담고 호출해도 9번 줄의 `other.read()`는 여전히 `A 2 true`입니다. `this`를 바깥 `Box`의 환경에서 찾기 때문입니다. 반면 10번 줄의 `other.plain(1, 2, 3)`은 `B 3 false`입니다. 일반 함수는 자기 `this`(`other.plain(...)`이라는 호출에서 정해지는 `other`), 자기 `arguments`(길이 `3`), 자기 `new.target`(`new` 없이 불렀으므로 `undefined`)를 가집니다([this](/concepts/this-binding)). 마지막으로 11번 줄의 `topLevel`은 어떤 함수 안에도 있지 않아 찾아 올라갈 곳에 `arguments`가 없습니다. 그래서 12번 줄의 `typeof arguments`는 `'undefined'`입니다. 선언되지 않은 이름에 `typeof`를 쓰면 오류 없이 `'undefined'`가 되기 때문이고, 같은 이름을 `typeof` 없이 읽으면 ReferenceError입니다. 객체 리터럴의 화살표 함수에서 `this`를 쓰는 경우나 `call`, `apply`, `bind`와의 관계는 [this](/concepts/this-binding)에서 다룹니다.

### 메서드 축약과 super

메서드 축약은 `m: function () {}`을 짧게 쓴 것과 같지 않습니다. 명세의 `DefineMethod`는 메서드를 만든 뒤 `MakeMethod`로 `[[HomeObject]]` 내부 슬롯에 그 메서드가 정의된 객체(여기서는 객체 리터럴이 만든 객체)를 넣습니다. `super.x`는 그 `[[HomeObject]]`의 `[[Prototype]]`에서 `x`를 찾기 시작합니다. `function` 식과 선언 안에서 `super` 프로퍼티를 쓰면 실행 전에 걸러지는 SyntaxError라서, 객체 리터럴에서 `super`를 쓰려면 메서드 축약으로 정의해야 합니다(그 안의 화살표 함수는 아래처럼 바깥 메서드의 `super`를 씁니다). `{ m: function () { super.x } }` 같은 줄이 하나라도 있으면 스크립트 전체가 실행되지 않으므로 이 SyntaxError는 예제로 보이지 않습니다.

예제 5의 6번 줄 `Object.setPrototypeOf(child, base)`는 `child`의 `[[Prototype]]`을 `base`로 정합니다([프로토타입 체인](/concepts/prototype-chain)). 3번 줄 `child.greet`의 `super.greet()`는 `child`의 `[[Prototype]]`인 `base`에서 `greet`을 찾아 `'base'`를 얻고 `'+child'`를 붙입니다. 4번 줄의 `later`는 안에 화살표 함수 `inner`를 만들어 `super.greet()`을 부릅니다. `inner`에는 자기 `super` 바인딩이 없어 `later`의 `super`를 쓰므로, 7번 줄에서 `child.later()`는 `'base'`입니다. 8~9번 줄은 `[[HomeObject]]`가 호출한 객체가 아니라 정의된 객체라는 점을 보입니다. `borrowed`에 `child.greet`를 옮겨 담고 `borrowed.greet()`를 불러도, 이 메서드의 `[[HomeObject]]`는 여전히 `child`라서 `super.greet()`는 `base`의 `greet`을 찾습니다. 결과는 `base+child`입니다. 다만 `[[HomeObject]]`가 정하는 것은 찾기 시작하는 곳뿐입니다. 찾아낸 `base.greet`에 넘어가는 `this`는 `[[HomeObject]]`가 아니라 호출 시점의 `this`(여기서는 `borrowed`)입니다. 예제의 `base.greet`는 `this`를 쓰지 않아 출력에는 드러나지 않습니다.

### 중복 매개변수

`function f(a, a)`처럼 같은 이름의 매개변수를 두 번 쓰는 것은 sloppy mode의 `function` 선언과 식에서, 매개변수 목록이 단순할(기본값·구조 분해·rest 파라미터가 없을) 때만 허용됩니다. 이때 `a`에는 뒤의 인수가 들어갑니다. `f(1, 2)`는 `2`를 돌려줍니다. 명세가 `function` 선언과 식에 중복 금지(UniqueFormalParameters) 규칙을 strict mode에서 적용하고, 그와 별도로 단순하지 않은 매개변수 목록(IsSimpleParameterList가 false)의 중복도 SyntaxError로 정하기 때문입니다. 그래서 sloppy mode라도 rest 파라미터가 있는 `function f(a, a, ...rest) {}`는 SyntaxError입니다. 반면 화살표 함수의 매개변수(ArrowFormalParameters)와 메서드 정의의 매개변수는 항상 UniqueFormalParameters라서 `(a, a) => 1`이나 `({ m(a, a) {} })`은 strict 여부와 관계없이 SyntaxError입니다.

SyntaxError는 실행 전에 걸러지는 오류라서 그런 줄이 하나라도 있으면 스크립트 전체가 한 줄도 실행되지 않습니다. 그래서 예제로 출력을 보일 수 없습니다. 아래 비교표의 마지막 행에도 들어 있습니다.

### rest 파라미터

rest 파라미터(`...이름`)는 선언한 매개변수에 대응하지 않는 나머지 인수를 모아 배열로 받습니다. 문법상 매개변수 목록의 맨 마지막에만 쓸 수 있어서 `(...a, b) => 1`은 SyntaxError입니다. 이 값은 명세의 바인딩 초기화가 ArrayCreate로 만든 진짜 배열이므로 `Array.isArray`가 `true`이고, 나머지 인수가 없으면 빈 배열입니다. `arguments`가 배열이 아니었던 것과 다릅니다. 또 `arguments`는 함수가 받은 모든 인수를 담지만 rest 파라미터는 선언한 매개변수 뒤의 나머지만 담습니다. 화살표 함수에는 자기 `arguments`가 없어도 rest 파라미터는 쓸 수 있습니다.

예제 6의 9번 줄에서 `sum(1, 2, 3)`은 1번 줄의 `...nums`가 `[1, 2, 3]`이 되어 `6`이고, `sum()`은 빈 배열이라 반복문이 돌지 않고 `0`입니다. 6번 줄의 `tag(label, ...rest)`는 10번 줄에서 `tag('a', 1, 2)`가 `rest`에 `[1, 2]`를 받아 `a:2:true`, `tag('b')`는 `rest`가 빈 배열이라 `b:0:true`입니다. 11번 줄은 함수의 `length`입니다. 명세의 ExpectedArgumentCount는 rest 파라미터를 세지 않으므로 `sum.length`는 `0`, `tag.length`는 `label` 하나만 세어 `1`입니다.

## 결과와 이유

### 예제 1

5번 줄에서 `double(4)`는 식 본문 `n * 2`의 값 `8`, `add(2, 3)`은 `5`입니다. 3번 줄의 `noReturn`은 본문이 `{`로 시작해 함수 본문으로 해석되고 `return`이 없어서 `undefined`이고, 4번 줄의 `withReturn`은 `5`입니다. 8번 줄에서 6번 줄의 `label()`은 `{ value: 1 }`이 객체가 아니라 본문이라 `undefined`를 돌려주고, 7번 줄의 `object()`는 괄호 덕분에 객체를 돌려주어 `JSON.stringify`가 `{"value":1}`을 만듭니다.

### 예제 2

4번 줄은 `normal`, `obj.short`, `arrow` 모두 `[[Call]]`이 있어 `function function function`입니다. 5번 줄의 `new normal()`과 `new obj.old()`는 둘 다 `MakeConstructor`가 불린 `function`이라 객체를 만들고 `object object`입니다. 6번 줄의 `new obj.short()`와 7번 줄의 `new arrow()`는 생성자가 아니라서 catch가 `TypeError`를 두 번 출력합니다. 8번 줄은 `prototype` 프로퍼티가 `normal`에만 있어 `true false false`입니다.

### 예제 3

10번 줄의 `count(1, 2, 3)`은 `arguments.length`가 `3`이고 `count()`는 `0`이라 `3 0`입니다. 11번 줄의 `second('x', 'y')`는 `a`가 `'x'`, `arguments[1]`이 `'y'`라서 `x y`입니다. 12번 줄의 `kind()`는 `arguments`가 배열이 아니라서 `Array.isArray(arguments)`가 `false`이고 `join`이 없어 `typeof arguments.join`이 `'undefined'`이므로 `false undefined`입니다.

### 예제 4

8번 줄의 `box.read(1, 2, 3)`에서 화살표 함수는 `this`, `arguments`, `new.target`을 모두 `Box`가 호출된 환경에서 찾으므로 `this.label`은 `'A'`, `arguments.length`는 `new Box('A', 'extra')`의 인수 수 `2`, `new.target === Box`는 `true`입니다. 9번 줄의 `other.read()`도 `read`가 `other`의 프로퍼티일 뿐 찾는 곳이 바뀌지 않아 같은 `A 2 true`입니다. 10번 줄의 `other.plain(1, 2, 3)`은 일반 함수라서 `this`가 `other`(`'B'`), `arguments.length`가 `3`, `new` 없이 불렀으니 `new.target === Box`가 `false`로 `B 3 false`입니다. 12번 줄의 `topLevel(1, 2)`는 찾아 올라가도 `arguments`가 없어 `typeof arguments`가 `undefined`입니다. 이것은 예제를 스크립트로 실행했을 때의 결과입니다. Node의 CommonJS 파일로 실행하면 호스트가 파일을 함수로 감싸 실행하므로 `arguments`가 있어 `'object'`가 나옵니다.

### 예제 5

3번 줄 `child.greet()`의 `super.greet()`는 `[[HomeObject]]`인 `child`의 `[[Prototype]]`(6번 줄에서 `base`로 정함)에서 `greet`을 찾아 `'base'`가 되고 `'+child'`가 붙어 `base+child`입니다. 4번 줄 `later` 안의 `inner`는 자기 `super`가 없어서 `later`의 `super`를 쓰고, `later`의 `[[HomeObject]]`가 `child`이므로 `base`의 `greet`이 불려 `'base'`입니다. 그래서 7번 줄은 `base+child base`입니다. 9번 줄의 `borrowed.greet()`는 `borrowed`로 불렀지만 `[[HomeObject]]`는 정의된 객체 `child`라서 같은 방식으로 `base+child`를 출력합니다(이때 `base.greet`의 `this`는 `borrowed`입니다).

### 예제 6

9번 줄에서 `sum(1, 2, 3)`은 `nums`가 `[1, 2, 3]`이라 합계 `6`이고, `sum()`은 `nums`가 빈 배열이라 `0`입니다. 10번 줄의 `tag('a', 1, 2)`는 `rest`가 `[1, 2]`라 길이 `2`에 배열이므로 `a:2:true`, `tag('b')`는 `rest`가 빈 배열이라 `b:0:true`입니다. 11번 줄에서 `sum.length`는 rest 파라미터를 세지 않아 `0`이고 `tag.length`는 `label` 하나만 세어 `1`입니다.

### 흔한 오해

<Callout type="misconception" title="화살표 함수는 function을 짧게 쓰는 문법일 뿐이다">

문법만 짧아진 것이 아닙니다. 화살표 함수는 `new`로 부를 수 없고 `prototype`이 없으며(예제 2), 자기 `this`, `arguments`, `new.target`, `super` 바인딩이 없어 바깥 것을 씁니다(예제 4, 예제 5). 매개변수 이름 중복도 strict 여부와 관계없이 SyntaxError입니다. `typeof`가 `'function'`이고 호출할 수 있다는 점만 같습니다.

</Callout>

<Callout type="misconception" title="메서드 축약은 m: function () {}을 줄여 쓴 것일 뿐이다">

둘 다 객체의 프로퍼티이고, 호출 방식(`o.m()`)으로 `this`가 정해지는 점은 같습니다. 하지만 메서드 축약은 생성자가 아니고 `prototype`이 없으며(예제 2), `[[HomeObject]]`가 있어 `super`를 쓸 수 있고(예제 5), 매개변수 이름이 중복되면 SyntaxError입니다. `m: function () {}`으로 쓴 함수는 반대로 `new`로 부를 수 있고 `prototype`이 있으며, 안에서 `super`를 쓰면 SyntaxError이고, sloppy mode이고 매개변수 목록이 단순하면 중복 매개변수도 허용됩니다.

</Callout>

<Callout type="misconception" title="화살표 함수는 만들 때의 this 값을 저장해 둔다">

화살표 함수는 `this` 값을 가지고 있는 것이 아니라 `this` 바인딩이 없을 뿐이고, `this`를 평가할 때마다 바깥 함수의 `this` 바인딩을 찾습니다. 파생 클래스의 생성자에서 이 차이가 드러납니다. `super()`를 부르기 전의 `this`는 초기화되지 않은 상태인데([클래스 상속과 super](/concepts/class-inheritance)), `var f = () => this`를 `super()` 앞에서 만들어 두고 `super()` 뒤에 `f()`를 부르면 초기화된 `this`가 나옵니다. 반대로 `super()` 앞에서 `f()`를 부르면 ReferenceError입니다. 만들 때 값을 저장해 두는 것이었다면 `super()` 앞에서 만든 `f`는 뒤에 불러도 초기화된 `this`를 얻을 수 없었을 것입니다. 결과는 `f()`를 부르는 시점의 바깥 `this` 바인딩 상태를 따릅니다. 두 경우를 실제로 실행해 확인했습니다.

</Callout>

<Callout type="misconception" title="arguments는 배열이다 / rest 파라미터와 같다">

`arguments`는 `length`와 인덱스 프로퍼티가 있지만 배열 객체가 아니라서 `Array.isArray`가 `false`이고, `[[Prototype]]`이 `Object.prototype`이라 `join` 같은 배열 메서드도 없습니다(예제 3). 진짜 배열로 바꾸는 방법은 있지만, 배열 메서드를 빌려 쓰는 방법은 배열로 바꾸는 용도로는 아직 다루지 않은 별도 개념이고 이터러블과 스프레드는 [이터러블과 for...of](/concepts/iterable-for-of)와 [스프레드와 디스트럭처링](/concepts/spread-destructuring)에서 다룹니다. rest 파라미터는 진짜 배열이고 선언한 매개변수 뒤의 나머지 인수만 담습니다(예제 6). 또 화살표 함수에는 자기 `arguments`가 없지만(예제 4) rest 파라미터는 쓸 수 있습니다.

</Callout>
